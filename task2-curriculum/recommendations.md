# Curriculum Recommendations

## 1. Purpose

These recommendations identify possible ways to improve the practical relevance of the curriculum to software-related roles. They are based on the courses recorded in my transcript for Semesters I–VI and ST-II, together with a preliminary comparison of three public job descriptions from **Amazon, Cisco and Wipro**.

The recommendations are provisional. Course titles and job descriptions alone cannot establish the full content, quality or redundancy of a course. Before implementing any change, the official syllabus, laboratory work, assessment methods, prerequisites, programme regulations and total credit requirements must be checked.

## 2. KEEP — Retain important foundations

### Recommendation 1: Retain programming and object-oriented programming foundations

**Courses:** CS101 — Computer Programming; CS201 — Object Oriented Programming Concepts.

**Reason:** Programming and object-oriented design are important foundations for software development. The Amazon Software Development Engineer Intern posting and Cisco Software Engineer posting provide relevant evidence for programming and software-engineering skills.

**Evidence and verification:** The selected postings provide a basis for reviewing the relevance of programming and OOP. Review the syllabi and practical assessments to confirm the languages taught and the amount of independent coding, debugging and problem-solving required.

**Proposed action:** KEEP the core learning outcomes while ensuring that students complete practical coding and debugging exercises.

### Recommendation 2: Retain data structures and algorithms

**Courses:** CS102 — Data Structures; CS203 — Design and Analysis of Algorithms.

**Reason:** Data structures, algorithms and problem-solving are important foundations for software engineering. The Amazon internship and Cisco Software Engineer postings provide relevant technical context for retaining these foundations.

**Evidence and verification:** Review the requirements stated in the Amazon and Cisco listings and compare them with the current lab exercises and assessments. Establish whether students implement data structures and analyse time and space complexity.

**Proposed action:** KEEP these subjects and preserve practical implementation and problem-solving components.

### Recommendation 3: Retain database and software engineering foundations

**Courses:** CS206 — Database Management Systems; CS304 — Software Engineering.

**Reason:** Database knowledge and structured software development are useful foundations for application development. The selected job-description sample provides stronger direct evidence for software development, testing and integration practices than for specific database requirements.

**Evidence and verification:** The selected postings support the broader relevance of software development, testing and application integration. They do not establish that the current database course lacks required content. Review the official syllabus, laboratory exercises and project assessments before deciding whether any database topics need to be added or revised.

**Proposed action:** KEEP the core subjects and update their practical exercises only where a syllabus and assessment review identifies a genuine gap.

## 3. UPDATE — Strengthen practical coverage

### Recommendation 4: Update web-development practical work

**Course:** CS205 — Web-Enabled Technologies.

**Reason:** The selected postings describe software-development, component-integration and testing responsibilities. These provide a reason to review practical application development and service integration, but they do not establish which frontend or backend frameworks are currently taught in the course.

**Proposed action:** UPDATE practical work, where gaps are confirmed, to include frontend-to-backend communication, API usage, input validation, error handling and basic application security.

**Evidence and verification:** Compare the official syllabus and lab exercises with the development, integration and testing responsibilities described in the selected postings. Do not assume that React, Angular, Spring Boot or .NET is already part of the course or that any particular framework must be added.

### Recommendation 5: Update database exercises to reflect application needs

**Course:** CS206 — Database Management Systems.

**Reason:** Applications often need to store, retrieve and protect data reliably. Database exercises can help students connect database concepts with practical application development. However, the selected job-description sample does not establish that the current database course has a specific coverage gap.

**Proposed action:** UPDATE practical exercises, if required, to include SQL queries, schema design, validation, transactions, access controls and database interaction from an application.

**Evidence and verification:** The selected postings support the broader relevance of software development, testing and application integration. They do not establish that the current database course lacks required content. Review the official syllabus, laboratory exercises and project assessments before deciding whether any database topics need to be added or revised. If these outcomes are already covered adequately, retain the current content rather than duplicating it.

### Recommendation 6: Strengthen testing and collaborative development

**Course:** CS304 — Software Engineering.

**Reason:** The selected job descriptions provide examples of software-development responsibilities and related engineering practices. Testing, debugging, collaboration and clear documentation can help students develop and maintain reliable software.

**Proposed action:** UPDATE project and lab assessments, where gaps exist, to include test cases, bug reports, version control, code review and documented fixes.

**Evidence and verification:** Confirm whether these activities already appear in the official course outcomes and assessments. The job descriptions provide context for the broader relevance of software-development practices but do not prove that the current course lacks them.

### Recommendation 7: Review cloud and service-integration practical work

**Courses:** CS307 — Cloud Computing; CS306 — Computer Networks.

**Reason:** Cloud systems, networking and service communication are relevant areas to investigate when preparing students for software-development work. The selected postings provide some technical context for software engineering and application integration, but they do not establish the depth of practical cloud coverage required by every role.

**Proposed action:** UPDATE practical work, if needed, with a small deployment exercise, service communication, configuration, access control and basic troubleshooting.

**Evidence and verification:** Review the syllabi and existing labs before adding content. Identify which outcomes are already taught and avoid introducing a duplicate module if the existing courses adequately cover them.

### Recommendation 8: Strengthen the connection between AI/data theory and practical work

**Courses:** DS101 — Introduction to AI and DS; DS203 — Data Science; DS304 — Machine Learning; DS307 — Big Data Systems; DS201 — Artificial Intelligence.

**Reason:** These course titles indicate coverage of AI and data-related areas. However, the selected job descriptions do not establish that every role requires advanced AI, machine learning or big-data skills. Improvements should therefore be justified by the learning outcomes of these courses rather than by assuming that all software roles require specialist AI skills.

**Proposed action:** UPDATE practical assessments where appropriate to include data preparation, model evaluation, interpretation of results, reproducible experiments and clear documentation.

**Evidence and verification:** Check the official syllabi, lab manuals and project rubrics. Confirm the course-code/title association for DS201 and verify the practical depth of each subject before deciding which changes are necessary.

### Recommendation 9: Make the internship and special project outcomes more demonstrable

**Courses:** IP201 — Internship-I; SP301 — Special Project.

**Reason:** Practical experience can help students demonstrate that they can apply concepts beyond written examinations. The Amazon internship posting provides relevant context for the value of internship experience in software-engineering preparation.

**Proposed action:** UPDATE assessment documentation, where appropriate, to require a project summary, individual contribution, technical decisions, testing evidence and a demonstration or presentation.

**Evidence and verification:** Check the existing internship and special-project assessment requirements. Retain any requirements already meeting these objectives. The selected postings should be treated as examples of employer expectations, not as proof that the current assessment process is inadequate.

## 4. ADD — Introduce practical learning only where gaps are confirmed

### Recommendation 10: Add a small API integration and debugging lab if no existing course covers it adequately

**Proposed learning outcomes:** Students should be able to call an API, validate input, handle errors, connect an application to a database and document debugging steps.

**Reason:** API integration and application communication are useful practical skills for application development and service integration.

**Proposed action:** ADD a short lab module within an appropriate existing course, rather than immediately creating a new full-credit subject, if a syllabus review identifies a genuine gap.

**Evidence and verification:** Review CS101, CS205, CS206 and CS304 first. If these outcomes are already covered, do not add a duplicate module.

### Recommendation 11: Add an integrated team project or capstone based on a real workflow

**Proposed project:** An assignment-submission and review management system based on the workflow investigated in Task 1.

**Reason:** A single project could let students apply programming, databases, web development, software engineering, testing and access control together.

**Proposed action:** ADD or adapt a project within a suitable existing project, laboratory or capstone component. Students could implement assignment publishing, submission receipts, status tracking, role-based access, validation, failure handling and testing using synthetic data.

**Evidence and verification:** Check the official project structure, available credits, prerequisites and assessment requirements before selecting the host course. The proposed system is a design concept, not a verified institutional requirement.

### Recommendation 12: Add targeted professional-development activities where existing coverage is insufficient

**Potential areas:** Technical documentation, presenting design decisions, teamwork, giving and receiving code-review feedback, and explaining debugging decisions.

**Reason:** These activities can help students communicate their work and collaborate during software development. The transcript includes Professional Communication and Power Skills courses, but their exact assessed outcomes are not available in this analysis.

**Proposed action:** ADD short, assessed activities within existing courses if the syllabus review identifies gaps. Do not create a new standalone course unless a broader curriculum review justifies it.

**Evidence and verification:** Review EG102, CR201, CR202, CR301 and CR302 course outcomes and assessments before proposing additional content.

## 5. REDUCE — Avoid premature credit reductions

No specific course is recommended for a credit reduction or removal based on the current evidence alone.

A limited sample of job advertisements cannot establish that a subject is unnecessary, redundant or unsuitable for the degree. Courses such as Blockchain Technology, Computer Vision, Electronics, Physics and other specialised or foundational subjects may serve programme, accreditation, prerequisite or elective requirements that are not visible in this comparison.

**Proposed action:** Conduct a syllabus and programme-requirements audit to identify any duplicated learning outcomes or topics that receive substantially more time than their intended outcomes justify. If duplication is demonstrated, consider reducing repeated content or reallocating some instructional time while preserving required learning outcomes.

Any credit reduction must be checked against the official programme structure, prerequisite dependencies, minimum-credit rules and applicable institutional requirements. No course should be removed solely because it has a “Limited” rating in the job-description mapping.

## 6. Prioritisation

The recommendations should be considered in this order:

1. Verify the official curriculum and course syllabi for the correct admission batch.
2. Inspect existing laboratory work and assessments to identify actual gaps.
3. Prioritise improvements to programming, databases, web development, software engineering and integrated practical work where evidence supports them.
4. Add short modules or project components only when existing coverage is insufficient.
5. Consider reductions only after confirming genuine duplication and compliance with programme requirements.
6. Calculate the credit impact using verified curriculum totals, including Semesters VII and VIII, before finalising the redesigned curriculum.

## 7. Limitations

This analysis covers 46 transcript entries recording 136 credits across Semesters I–VI and ST-II. These figures represent the available transcript records only and do not establish the total credit requirement for the complete B.Tech CSE programme.

A semester-wise B.Tech CSE curriculum reference is available for comparison, but its applicability to the 2023–2027 admission batch has not been confirmed. Some semester, course and credit details in the supplied reference are ambiguous and require verification against the applicable official curriculum.

The job-description sample contains three selected postings from Amazon, Cisco and Wipro and is not representative of the entire software industry. The postings also have different eligibility conditions. The Amazon Software Development Engineer Intern posting targets students graduating in 2027; the Cisco Software Engineer listing indicated that applications were closed when checked on 24 October 2026; and the Wipro Junior .NET Software Engineer Channels listing requires 3–5 years of experience. The Wipro role is therefore included as a technical-skills comparator, not as a direct fresher opportunity. The Cisco listing should likewise not be presented as an open vacancy based on the status observed during this analysis.

Course-to-job ratings are preliminary interpretations of transcript course titles and advertised requirements, not verified syllabus-level matches. The selected postings provide examples of particular employer requirements, not a comprehensive picture of the software industry or proof that a particular course needs modification.

Course titles alone cannot establish the depth of practical coverage, duplication between subjects or the need to remove credits. The recommendations therefore remain provisional until the official curriculum, detailed syllabi, laboratory work and assessment requirements have been reviewed.

The recommendations are proposals for further review, not confirmed faculty decisions. No formal faculty or graduate feedback was obtained for this analysis. Any future feedback should be documented accurately and distinguished from the author's own observations.
